# 红石LIB（Redstone Chan Lib）

一个给作者自己用的 Minecraft NeoForge 1.21.1 前置库。目前包含两部分内容：

- 通用注册设施（方块、物品、粒子等）
- 一套可完全自定义的传送门系统

传送门系统是本库的主体。它的目标是把“一座传送门长什么样、怎么点亮、通向哪里”从代码里搬到数据包里，让整合包作者不写 Java 也能做出自己的传送门。

## 传送门系统能自定义什么

- 外围框架方块：一个方块列表，或者方块标签
- 激活方式：物品、物品标签、流体、流体标签或空手，可以同时配置多种
- 仪式式激活：地面留出流体池、外圈摆框架、往流体里丢物品，一道雷把门点亮（暮色森林式）
- 传送门方块颜色：ARGB 颜色，默认是原版下界门那种紫色，写什么颜色就是什么颜色
- 传送门方块名称：显示在方块名称上
- 目标维度：点亮后玩家被送往哪个维度
- 摆放类型：竖直的门（像下界门）、平铺在地面的门（像末地传送门），或者两种都行
- 内部尺寸范围与传送等待时间

## 默认行为

模组自带一个测试用定义 `redstone_chan_lib:test`，配置如下：

- 外围框架：钻石块
- 激活方式：钻石，或者手持水桶（水）
- 颜色：默认（原版紫）
- 名称：测试
- 目标维度：下界

用钻石块摆出一个内部至少 2×3 的矩形框，手持钻石右键任意一个框架方块，门内就会填满传送门方块；拿着水桶右键同一个框架也可以点亮，水桶会变成空桶。走进去等待约 4 秒（80 刻）就会被传送到下界；在下界会寻找同款传送门，找不到就自动造一座。反向进入同样会回到主世界，主世界与下界之间按 8 倍坐标换算。

破坏传送门方块会拆掉整座门；破坏框架方块时，如果这块方块正好是某座已点亮传送门的外圈框架，也会一并拆除，不会留下半座悬空的门。拆除的每一格传送门方块都会播放原版的方块破坏音效。只是“材质相同”的方块不算框架 —— 在门旁边贴一块同材质的方块再拆掉它，门不会跟着碎。

### 竖直门与横门

默认的摆放类型是 `any`，同一个定义既接受竖直的框架，也接受平铺在地面上的框架，判定方式是同一个：右键任意一个框架方块。

横门和末地传送门一样躺在地上，框架围成一片矩形，门方块占据中间那片地面。点亮时手持激活物品右键任意一个框架方块，从侧面点同样有效。进入横门后等待时间结束，也会被传送到目标维度；目标维度新建的门同样保持横向，避免出现“从横门掉进竖门墙里”的情况。

横门的内部尺寸意义与竖门一致，只是宽度沿 X 轴、高度沿 Z 轴；玩家站的那一层就是门方块所在的层，所以整片门下面都要有实心方块托着。模组自带一份横向门的示例定义（金块框架，钻石激活），可以直接拿来做参考。

### 仪式式传送门

第三种玩法是暮色森林式的仪式：在地面上留出一片和地面齐平的流体池，在池子四周那些方块的**上方**摆上框架方块（最常见的摆法就是在水池边上一圈草方块的顶面插满花），然后往流体里丢入指定物品。物品整个沉进流体、打好一道雷之后，空位里的流体随即变成传送门方块，人可以走进去。

几点规则：

- 空位是同一层平面上的流体矩形，大小由定义指定（默认 2×2），必须恰好是这么多格
- 空位里的流体必须是源方块（静止的水），流动的液体不算
- 框架方块摆在水池四周那一圈方块的上方：池子边上的方块要能托住方块（比如草方块、石头），它上面那一格才是框架方块；外圈四条边每一格上方都要有，四个角可以留空
- 物品要整个沉进流体之后才会触发，浮在液面上或者还在半空中时不会点亮
- 触发后会消耗一个物品，并打出真实的闪电（会点燃方块、会劈伤附近的实体）
- 定义里可以要求“每种框架方块都要用到”，也可以限定丢进去的物品或物品标签

模组自带三份测试定义：常规的钻石块框架门（`redstone_chan_lib:test`）、平铺在地面的横门（`redstone_chan_lib:test_flat`）、水池插花的仪式门（`redstone_chan_lib:test_ritual`），可以直接拿来做参考。

定义既可以写成数据包 JSON，也可以在 Java 里注册。两种写法的字段、示例和可用方法都整理在 [README_USAGE.md](README_USAGE.md) 里。
