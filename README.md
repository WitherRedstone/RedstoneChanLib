# 红石LIB（Redstone Chan Lib）

一个给作者自己用的 Minecraft NeoForge 1.21.1 前置库。目前包含四部分内容：

- 通用注册设施（方块、物品、粒子等）
- 一套可完全自定义的传送门系统
- 一个纯 Java 调用的生物描边接口
- 一个纯 Java 调用的方块描边接口，外加“扫描周围特定方块并高亮”

传送门系统是本库的主体。它的目标是把“一座传送门长什么样、怎么点亮、通向哪里”从代码里搬到数据包里，让整合包作者不写 Java 也能做出自己的传送门。

## 传送门系统能自定义什么

- 外围框架方块：一个方块列表，或者方块标签
- 激活方式：物品、物品标签、流体、流体标签或空手，可以同时配置多种
- 仪式式激活：地面留出流体池、外圈摆框架、往流体里丢物品，一道雷把门点亮（暮色森林式）
- 传送门方块颜色：ARGB 颜色，默认是原版下界门那种紫色，写什么颜色就是什么颜色
- 传送门方块名称：显示在方块名称上
- 目标维度：点亮后玩家被送往哪个维度
- 摆放类型：竖直的门（像下界门）、平铺在地面的门（像末地传送门），或者两种都行
- 内部尺寸范围与传送等待时间

## 默认行为

模组自带一个测试用定义 `redstone_chan_lib:test`，配置如下：

- 外围框架：钻石块
- 激活方式：钻石，或者手持水桶（水）
- 颜色：默认（原版紫）
- 名称：测试
- 目标维度：下界

用钻石块摆出一个内部至少 2×3 的矩形框，手持钻石右键任意一个框架方块，门内就会填满传送门方块；拿着水桶右键同一个框架也可以点亮，水桶会变成空桶。走进去等待约 4 秒（80 刻）就会被传送到下界；在下界会寻找同款传送门，找不到就自动造一座。反向进入同样会回到主世界，主世界与下界之间按 8 倍坐标换算。

破坏传送门方块会拆掉整座门；破坏框架方块时，如果这块方块正好是某座已点亮传送门的外圈框架，也会一并拆除，不会留下半座悬空的门。拆除的每一格传送门方块都会播放原版的方块破坏音效。只是“材质相同”的方块不算框架 —— 在门旁边贴一块同材质的方块再拆掉它，门不会跟着碎。

### 竖直门与横门

默认的摆放类型是 `any`，同一个定义既接受竖直的框架，也接受平铺在地面上的框架，判定方式是同一个：右键任意一个框架方块。

横门和末地传送门一样躺在地上，框架围成一片矩形，门方块占据中间那片地面。点亮时手持激活物品右键任意一个框架方块，从侧面点同样有效。进入横门后等待时间结束，也会被传送到目标维度；目标维度新建的门同样保持横向，避免出现“从横门掉进竖门墙里”的情况。

横门的内部尺寸意义与竖门一致，只是宽度沿 X 轴、高度沿 Z 轴；玩家站的那一层就是门方块所在的层，所以整片门下面都要有实心方块托着。模组自带一份横向门的示例定义（金块框架，钻石激活），可以直接拿来做参考。

### 仪式式传送门

第三种玩法是暮色森林式的仪式：在地面上留出一片和地面齐平的流体池，在池子四周那些方块的**上方**摆上框架方块（最常见的摆法就是在水池边上一圈草方块的顶面插满花），然后往流体里丢入指定物品。物品整个沉进流体、打好一道雷之后，空位里的流体随即变成传送门方块，人可以走进去。

几点规则：

- 空位是同一层平面上的流体矩形，大小由定义指定（默认 2×2），必须恰好是这么多格
- 空位里的流体必须是源方块（静止的水），流动的液体不算
- 框架方块摆在水池四周那一圈方块的上方：池子边上的方块要能托住方块（比如草方块、石头），它上面那一格才是框架方块；外圈四条边每一格上方都要有，四个角可以留空
- 物品要整个沉进流体之后才会触发，浮在液面上或者还在半空中时不会点亮
- 触发后会消耗一个物品，并打出真实的闪电（会点燃方块、会劈伤附近的实体）
- 定义里可以要求“每种框架方块都要用到”，也可以限定丢进去的物品或物品标签

模组自带三份测试定义：常规的钻石块框架门（`redstone_chan_lib:test`）、平铺在地面的横门（`redstone_chan_lib:test_flat`）、水池插花的仪式门（`redstone_chan_lib:test_ritual`），可以直接拿来做参考。

## 生物描边

除了传送门，库里还有一个纯 Java 调用的生物描边接口 `EntityOutline`，给其他模组用：干什么事情之后，让某只生物在客户端亮起一圈边。

三种模式：

- `GLOW` 发光描边，颜色可以自定义；也可以选彩色，彩色会沿着轮廓同时铺开好几种颜色，并慢慢流动
- `BLACK` 黑色描边
- `HIGHLIGHT` 高光，加法混合，看起来最亮

描边粗细可以调，默认是 0.08 格，想要更粗就传个更大的值；做法和原版发光效果一样，是在屏幕上贴着轮廓摊开一圈光晕，所以不会出现贴图被拉伸、部件拼不上的问题，边缘还带一点由内向外的散发感。

推荐在服务端调用：设置会写进世界存档，并同步给所有能看到这只生物的玩家，所以玩家退出重进、区块重新加载之后描边还在。想先看看效果：对着生物按 `K`，会依次切换“发光（青色）→ 发光（彩色）→ 黑色 → 高光 → 发光（青色，被挡住就不画）→ 取消描边”，并在动作栏提示当前是哪种，日志里也会打一条。

## 方块描边

同一个包里还有方块描边接口 `BlockOutline`，用法和生物描边一致，目标换成“维度 + 坐标”，适合标出某个机器、箱子或结构。

五种模式：

- `GLOW` 发光描边，颜色可以自定义，也可以选彩色（同一瞬间一圈方框上就有好几种颜色，并缓慢流动）
- `BLACK` 黑色描边
- `HIGHLIGHT` 高光，加法混合，看起来最亮
- `CREATE` 机械动力风格：一圈蓝色的方棱柱棱线（默认 `#65CAFC`），出现时由细变粗、到最粗后保持一会儿，再在原地变细消失；可以设成一直显示，也可以设保持的秒数
- `WIRE` 线框：十二条棱各画一条细线（默认 1 像素，最多 4 像素），不画实心方条，所以最细、最干净，适合一次标很多方块

方块的描边是直接画包围盒的十二条棱，所以粗细固定是屏幕像素，远看近看都一样粗；机械动力风格的那根棱是实心方棱柱，从任何角度看都一样粗、拐角也是实心的。也可以选择“被方块挡住就不画”，或者隔着墙也能看见。

## 方块扫描高亮

`BlockScanOutline` 是“给一个配方，扫描玩家周围符合条件的方块并全部高亮”，效果类似探矿类模组：拿到之后周围的矿就亮起来。

目标是方块列表、方块标签列表，或者两者混用；扫描以玩家为中心，半径可以自己定（默认 16 格，最大 48 格）。高亮方式沿用上面那些模式，默认是 `WIRE` 线框并且穿透方块——探矿就是要看见墙里的矿，而且一次标几十上百个方块时线框不会糊成一片。

颜色可以统一给一种，也可以按标签或按方块单独配：内置的 `oreTagColors()` 用的是 NeoForge 的 `c:ores/xxx` 矿词标签，所以别的模组的同类矿石会跟着自动上色；标签没覆盖到的再用 `withColor(...)` 按方块补。优先级是“方块 → 标签 → 统一颜色”。调用时也可以用 `BlockScanOutline.scan(...)` 直接一条条往下写颜色，比如 `.color(BlockTags.IRON_ORES, 0xFFD8AF93)`。

想先看看效果：在游戏里按 `J`，会开关周围所有矿石的扫描（线框、穿透方块、半径 16 格，每种矿用自己的颜色），动作栏会提示“扫描：显示周围矿石 / 已关闭”。

## 实体扫描高亮

`EntityScanOutline` 和方块扫描是一对，扫的是实体：目标是实体类型列表、实体标签列表或两者混用，命中的实体把碰撞箱画成一圈线框，同样是默认 `WIRE` 线框并且穿透方块。

半径默认 16 格、最大 64 格；扫描每 10 tick 重扫一次，实体走开或者死掉高亮会自己消失。和方块扫描一样，客户端调用立刻生效，服务端调用会写进该维度存档并同步给同维度玩家。

想先看看效果：在游戏里按 `L`，准星对着某个实体时开关“扫描这个实体的同类”（橙色线框）。

调用方式和可用方法见 [README_USAGE.md](README_USAGE.md)。
